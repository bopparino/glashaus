# Terminal Pastoralism — visual horizon

Confirmed direction from the user on September 28, 2026. This supersedes Prism as the intended finished visual direction. The existing web interface remains the implementation baseline while assistant capabilities are built; a native visual design pass will translate this direction into real screens.

## Reference evidence

- Interface moodboard (private reference): near-black equipment surfaces, warm paper panels, thin rules, compact monospaced metadata, wide tracking, sparse rust-red signals, field imagery, archive and daily-log layouts.
- World moodboard (private reference): rural domestic life beside immense aging infrastructure; overcast light, desaturated olive/stone, useful machinery, weathered materials, human scale and quiet persistence.
- Motion reference (private reference): 28.001 seconds, 1080 × 608, 24 fps. Twelve timestamped frames are retained under `visual-references/frames`. Visual sampling shows authentication, modular alignment/status panels, a central signal display, orbital geometry, and a late red alert state. Audio has not been evaluated.

The source files are private reference material supplied by the user and are intentionally excluded from this distribution. ## Translation into Glashaus

The companion should feel like a familiar personal instrument: capable, legible, quietly present, and comfortable to return to for an evening. Preserve the contrast between warm conversation and precise machine status.

- **Material:** carbon/charcoal, warm bone, fog/stone, muted olive. Use texture in restrained image regions and display surfaces; protect body text from grain.
- **Type:** narrow display typography and monospaced timestamps/status can carry the reference. Conversation and native controls remain readable, scalable, and accessible. Do not reproduce the moodboards' tiny metadata at literal size.
- **Structure:** open aligned rows, restrained framing, generous reading space, small clear status labels. Conversation remains the center; Activity communicates commitments and actual action outcomes.
- **Imagery:** rural horizons, distant machinery, domestic stillness, weather, and natural reclamation. Author individual assets for selected layouts later. Avoid treating the entire moodboard as a background image.
- **Signal:** rust red for meaningful warnings/destructive actions. The video's luminous green is a motion/status reference; its final role in the palette remains a design decision to review.
- **Motion:** stepped reveals and precise state transitions can identify connection, listening, processing, and completion. Pace them for repeated daily use. No flashing alert sequence or simulated startup delay is required by the reference. Respect Reduce Motion and never animate every streamed token.
- **Truth:** show connection state, recording state, due times, and action receipts only from actual application state. Decorative orbital motifs must not impersonate sensors or service activity.
- **Native behavior:** use iOS navigation, sheets, system gestures, keyboard behavior, safe areas, Dynamic Type, VoiceOver, and adequate touch targets. This is a native app inspired by the references, not a literal desktop terminal pasted into a phone.

## Finished-design milestone

The owner selected native option 1 on September 28: Activity-first Field Ledger. Its approved image and direction contract are in `ios/Design/`. Activity, conversation, connections, memories, journal, setup, and recovery use this native direction. Voice and other future capabilities will extend it when implemented. Verify on the target iPhone, including long conversations, large type, reduced motion, offline state, interrupted audio when available, expired connections, and pending actions.

Completion evidence: approved native visual target; documented color/type/spacing/motion tokens; real asset provenance; functional navigation and controls; simulator and real-device captures; accessible content; and a clear distinction between available, disconnected, and planned capabilities.

This is a horizon and constraint record, not an approved screen composition or completed redesign.
